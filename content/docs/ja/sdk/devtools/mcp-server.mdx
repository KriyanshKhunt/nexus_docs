**Model Context Protocol (MCP)** を使用すると、AIコーディングアシスタント（Cursor、Claude Desktop、Windsurfなど）は、自然言語を使用してエディターからワークフロー、購読者、オブジェクト、ブロードキャスト、およびガイドを直接管理できます。

---

## IDE の設定

エディターのMCP設定ファイルにサーバーを設定します。

### 環境変数

| 変数               | 必須     | 説明                               | デフォルト              |
| :----------------- | :------- | :--------------------------------- | :---------------------- |
| `NEXUS_SECRET_KEY` | **はい** | 環境のAPIシークレットキー (`sk_*`) |                         |
| `NEXUS_BASE_URL`   | いいえ   | APIエンドポイントのベースURL       | `http://localhost:5000` |

---

### 設定ファイル

#### 1. Claude Desktop

グローバル設定ファイルに設定を追加します：

- **macOS / Linux**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "nexus-signal": {
      "command": "npx",
      "args": ["-y", "@nexus-signal/mcp-server@latest"],
      "env": {
        "NEXUS_SECRET_KEY": "sk_prd_your_secret_key",
        "NEXUS_BASE_URL": "https://api.nexussignal.dev"
      }
    }
  }
}
```

#### 2. Cursor

**Settings → Features → MCP** に移動し、**Add New MCP Server** をクリックして以下を構成します：

- **Name**: `nexus-signal`
- **Type**: `command`
- **Command**: `npx -y @nexus-signal/mcp-server@latest`
- **Environment Variables**: `NEXUS_SECRET_KEY` と `NEXUS_BASE_URL` をキー値ペアとして追加します。

#### 3. Windsurf

`~/.codeium/windsurf/mcp_config.json` に設定を追加します：

```json
{
  "mcpServers": {
    "nexus-signal": {
      "command": "npx",
      "args": ["-y", "@nexus-signal/mcp-server@latest"],
      "env": {
        "NEXUS_SECRET_KEY": "sk_prd_your_secret_key",
        "NEXUS_BASE_URL": "https://api.nexussignal.dev"
      }
    }
  }
}
```

## MCP プリミティブ

サーバーは、モデルが通知設定を探索および実行できるように、**30のツール**、**4つのリソース**、および**5つのプロンプト**を公開しています。

### 1. ツール (Tools)

ツールを使用すると、AIエージェントはワークスペースで読み取り/書き込み操作を実行できます：

#### ワークフロー

- `nexus_list_workflows` — 現在の環境のワークフローを一覧表示します。
- `nexus_get_workflow` — 名前でワークフローのステップ設定を取得します。
- `nexus_trigger_workflow` — 複数の受信者に対してワークフローをトリガーします。
- `nexus_send_notification` — 単一の受信者にワークフロー通知を送信します。
- `nexus_sync_workflows` — コード定義のワークフローを同期します。
- `nexus_get_delivery_status` — ログUUIDで配信ステータスを検査します。

#### 購読者

- `nexus_list_subscribers` — 受信者を検索してフィルターします。
- `nexus_get_subscriber` — IDで購読者の詳細を取得します。
- `nexus_create_subscriber` — 購読者フィールドをアップサートします。
- `nexus_delete_subscriber` — 購読者と履歴を削除します。

#### オブジェクト

- `nexus_set_object` — ユーザー以外のエンティティを作成または更新します。
- `nexus_get_object` — オブジェクトの詳細と購読者数を取得します。
- `nexus_subscribe_to_object` — オブジェクトを監視する購読者を追加します。
- `nexus_unsubscribe_from_object` — オブジェクトから購読者を削除します。

#### B2Bテナント

- `nexus_list_tenants` — テナントのブランド設定を取得します。
- `nexus_create_or_update_tenant` — テナント設定をアップサートします。

#### オーディエンスとセグメント

- `nexus_list_audiences` — 動的なオーディエンスセグメントを取得します。
- `nexus_create_audience` — 論理ルールに基づいてセグメントを作成します。

#### ブロードキャスト

- `nexus_list_broadcasts` — ブロードキャストとその状態を照会します。
- `nexus_create_broadcast` — オーディエンスへのワークフロー送信を準備します。
- `nexus_send_broadcast` — ブロードキャストを即座に送信します。

#### コンテンツとレイアウト

- `nexus_list_layouts` — 共有メールレイアウトを取得します。
- `nexus_create_or_update_layout` — 共有メールレイアウトを作成します。
- `nexus_list_translations` — 翻訳辞書とローカル言語を表示します。
- `nexus_upsert_translation` — ローカル言語のキー値翻訳辞書をアップサートします。

#### プロダクト内ガイド

- `nexus_list_guides` — プロダクト内ガイド（バナー、モーダル、ツールチップ）をリスト表示します。
- `nexus_get_guide` — ガイドの設計スキーマを取得します。
- `nexus_create_or_update_guide` — ガイド属性をアップサートします。

#### スケジュールとシステム

- `nexus_list_schedules` — アクティブな反復cronワークフローをリスト表示します。
- `nexus_check_health` — APIとの接続状態を確認します。

---

### 2. リソース (Resources)

リソースは、AIモデルに読み取り可能なコンテキストドキュメントを提供します：

- `nexus://docs/integration-guide` — Node.jsのクイックスタート。
- `nexus://docs/step-types` — delay、digest、channel、およびhttpFetchステップのリファレンススキーマ。
- `nexus://docs/channels` — サポートされているチャネルと必須の連絡先フィールド。
- `nexus://workflows/{name}` — アクティブなワークフローの設定JSON。

---

### 3. プロンプト (Prompts)

プロンプトは、モデルがタスクを構造化するのに役立つ事前構成されたテンプレートです：

- `setup-transactional-workflow` — チャネルフォールバックと遅延を備えたトランザクションフローの設計を支援します。
- `setup-digest-workflow` — 通知のバッチ処理とインapp/メールダイジェストを準備します。
- `setup-escalation-workflow` — 優先度に基づいてエスカレーションチェーン (`in-app` → `email` → `SMS`) を作成します。
- `setup-object-fanout` — オブジェクトの作成、購読者の追加、およびワークフローのトリガーを行います。
- `debug-delivery` — ログと優先設定を使用して、失敗した配信をデバッグするようにモデルをガイドします。
