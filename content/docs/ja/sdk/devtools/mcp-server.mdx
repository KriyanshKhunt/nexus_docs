**Model Context Protocol (MCP)** サーバーを使用すると、AI コーディングアシスタント（Cursor、Claude Desktop、Windsurf など）が、自然言語を使用してエディタから直接、ワークフロー、サブスクライバー、オブジェクト、ブロードキャスト、およびガイドを管理できます。

---

## IDE でのセットアップ & 構成

エディタの MCP 設定ファイルにサーバーを構成します。

### 環境変数

| 変数               | 必須     | 説明                                      | デフォルト              |
| :----------------- | :------- | :---------------------------------------- | :---------------------- |
| `NEXUS_SECRET_KEY` | **はい** | 環境固有のシークレット API キー（`sk_*`） |                         |
| `NEXUS_BASE_URL`   | いいえ   | API エンドポイントのベース URL            | `http://localhost:5000` |

---

### 設定ファイル

#### 1. Claude Desktop

グローバル設定ファイルに設定を追加します。

- **macOS / Linux**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "nexus-signal": {
      "command": "npx",
      "args": ["-y", "@nexus-signal/mcp-server@latest"],
      "env": {
        "NEXUS_SECRET_KEY": "sk_prd_your_secret_key",
        "NEXUS_BASE_URL": "https://api.nexussignal.dev"
      }
    }
  }
}
```

#### 2. Cursor

**Settings → Features → MCP** に移動し、**Add New MCP Server** をクリックして以下のように構成します。

- **Name**: `nexus-signal`
- **Type**: `command`
- **Command**: `npx -y @nexus-signal/mcp-server@latest`
- **Environment Variables**: キーと値のペアとして `NEXUS_SECRET_KEY` と `NEXUS_BASE_URL` を追加します。

#### 3. Windsurf

`~/.codeium/windsurf/mcp_config.json` に以下を追加します。

```json
{
  "mcpServers": {
    "nexus-signal": {
      "command": "npx",
      "args": ["-y", "@nexus-signal/mcp-server@latest"],
      "env": {
        "NEXUS_SECRET_KEY": "sk_prd_your_secret_key",
        "NEXUS_BASE_URL": "https://api.nexussignal.dev"
      }
    }
  }
}
```

## MCP プリミティブ

サーバーは、LLM が通知設定を探索および実行できるように、**30種類のツール**、**4種類のリソース**、および**5種類のプロンプト**を公開しています。

### 1. ツール (Tools)

ツールを使用すると、AI エージェントはワークスペースに対して書き込み/読み取り操作を実行できます。

#### ワークフロー (Workflows)

- `nexus_list_workflows` — 現在の環境のワークフローをリストします。
- `nexus_get_workflow` — 指定した名前のワークフロー構成ステップを取得します。
- `nexus_trigger_workflow` — 複数の受信者に対してワークフローを実行します。
- `nexus_send_notification` — 単一の受信者にワークフローを送信します。
- `nexus_sync_workflows` — コードで定義されたワークフロー定義をプッシュします。
- `nexus_get_delivery_status` — ログ UUID の配信状態を検査します。

#### サブスクライバー (Subscribers)

- `nexus_list_subscribers` — 受信者を検索します。
- `nexus_get_subscriber` — ID でサブスクライバーの詳細を取得します。
- `nexus_create_subscriber` — サブスクライバーの連絡先フィールドを作成/更新します。
- `nexus_delete_subscriber` — サブスクライバーとその履歴を永久に削除します。

#### オブジェクト (Objects)

- `nexus_set_object` — ユーザー以外のエンティティを作成または更新します。
- `nexus_get_object` — オブジェクトの詳細とサブスクライバー数を取得します。
- `nexus_subscribe_to_object` — オブジェクトを監視するサブスクライバーを追加します。
- `nexus_unsubscribe_from_object` — オブジェクトの監視サブスクライバーを解除します。

#### B2B テナント (B2B Tenants)

- `nexus_list_tenants` — テナントのブランディング情報を取得します。
- `nexus_create_or_update_tenant` — テナント構成を作成/更新します。

#### オーディエンス & セグメント (Audiences & Segments)

- `nexus_list_audiences` — 動的なオーディエンスセグメントを取得します。
- `nexus_create_audience` — 論理ルールを使用してセグメントを作成します。

#### ブロードキャスト (Broadcasts)

- `nexus_list_broadcasts` — ブロードキャストとステータスを表示します。
- `nexus_create_broadcast` — オーディエンスへのワークフロー送信を設定します。
- `nexus_send_broadcast` — ブロードキャストを即座に配信します。

#### コンテンツ & レイアウト (Content & Layouts)

- `nexus_list_layouts` — メールの HTML ラッパーレイアウトを取得します。
- `nexus_create_or_update_layout` — 共有メールレイアウトを作成します。
- `nexus_list_translations` — ローカライズバンドルをリストします。
- `nexus_upsert_translation` — ローカライズのキー値辞書を作成または更新します。

#### アプリ内ガイド (In-Product Guides)

- `nexus_list_guides` — アプリ内バナー/モーダル/ツールチップの設定をリストします。
- `nexus_get_guide` — ガイドのレイアウトスキーマを取得します。
- `nexus_create_or_update_guide` — ガイド属性を作成/更新します。

#### スケジュール & システム (Schedules & System)

- `nexus_list_schedules` — アクティブな定期実行 cron ワークフローを表示します。
- `nexus_check_health` — API 接続ステータスを確認します。

---

### 2. リソース (Resources)

リソースは、読み取り専用のコンテキストドキュメントを AI モデルに提供します。

- `nexus://docs/integration-guide` — Node.js のクイックスタート例。
- `nexus://docs/step-types` — delay、digest、channel、および httpFetch の参照スキーマ。
- `nexus://docs/channels` — サポートされているチャネルと必要な連絡先フィールド。
- `nexus://workflows/{name}` — 構成されたワークフローのライブ JSON スキーマ。

---

### 3. プロンプト (Prompts)

プロンプトは、モデルがタスクを調整するのに役立つ事前構成されたテンプレートとして機能します。

- `setup-transactional-workflow` — チャネルフォールバックと遅延を備えたトランザクションパスの設計を支援します。
- `setup-digest-workflow` — 通知のバッチ処理とメール/アプリ内の要約の構造を作成します。
- `setup-escalation-workflow` — 優先度に基づいてエスカレーションチェーン（`アプリ内` → `メール` → `SMS`）を作成します。
- `setup-object-fanout` — オブジェクトを作成し、サブスクライバーを追加して、ワークフローをトリガーします。
- `debug-delivery` — ログ ID と環境設定から失敗した配信をデバッグするようにモデルを案内します。
