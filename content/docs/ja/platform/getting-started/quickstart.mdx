# クイックスタート

このガイドでは、最初の通知イベントを送信し、リアルタイムの配信ログを確認する手順を説明します。

<Steps>
<Step>
### ワークスペースの作成とキーの取得

[Nexus ダッシュボード](https://app.nexussignal.dev)にログインします。ワークスペースには、**完全に分離された3つの環境**が事前に構成されています。

| 環境            | キーの接頭辞          | 目的                                                               |
| :-------------- | :-------------------- | :----------------------------------------------------------------- |
| **Development** | `pk_dev_` / `sk_dev_` | ローカルのステージング、開発者用サンドボックス、および模擬テスト。 |
| **Staging**     | `pk_stg_` / `sk_stg_` | 内部テスト、QA パイプライン、およびステージングブランチ。          |
| **Production**  | `pk_prd_` / `sk_prd_` | 本番トラフィックおよびライブユーザー通知。                         |

**Settings → API Keys** に移動し、現在のアクティブな環境のキーをコピーします。

</Step>

<Step>
### 最初のワークフローの設計

1. ダッシュボードの **Workflows** ページに移動します。
2. **Create Workflow** をクリックし、イベントトリガーの名前を `user.welcome` に設定します。
3. ビジュアルキャンバスで、プライマリトリガーのすぐ下に **Email Channel Node** をドラッグ＆ドロップします。
4. Email ノードをクリックして、その件名（例: `Welcome to Acme, {{ data.name }}!`）と標準テンプレートレイアウトを構成します。
5. **Publish** をクリックして、ワークフローテンプレートをアクティブな環境にデプロイします。

</Step>

<Step>
### 配信プロバイダーの接続 (BYOP)

Nexus は、通知を発送するために配信ゲートウェイを必要とします。

1. ダッシュボードの **Integrations** タブに移動します。
2. 任意のプロバイダー（例: **SendGrid**、**Resend**、または **Twilio**）を選択します。
3. プロバイダーの API 資格情報を入力します。資格情報は AES-256 を使用して保管時に完全に暗号化され、実行の瞬間にのみ復号されます。

</Step>

<Step>
### SDK のインストール

Nexus は、ワークフロートリガー用のサーバー側 SDK と、リアルタイムのアプリ内フィード用のフロントエンドコンポーネントの両方をサポートしています。

#### サーバー側 SDK (Node.js / Express)

<Tabs items={['npm', 'pnpm', 'yarn']}>
  <Tab value="npm">```bash npm install @nexus-signal/node ```</Tab>
  <Tab value="pnpm">```bash pnpm add @nexus-signal/node ```</Tab>
  <Tab value="yarn">```bash yarn add @nexus-signal/node ```</Tab>
</Tabs>

#### クライアント側 SDK (React / Next.js)

<Tabs items={['npm', 'pnpm', 'yarn']}>
  <Tab value="npm">```bash npm install @nexus-signal/react lucide-react ```</Tab>
  <Tab value="pnpm">```bash pnpm add @nexus-signal/react lucide-react ```</Tab>
  <Tab value="yarn">```bash yarn add @nexus-signal/react lucide-react ```</Tab>
</Tabs>

</Step>

<Step>
### イベントのトリガー

バックエンドサーバーにスクリプトを作成してクライアントを初期化し、`user.welcome` ワークフローをトリガーします。

```ts title="trigger.ts"
import { NexusClient } from '@nexus-signal/node';

// シークレットキーでクライアントを初期化（サーバー専用）
const nexus = new NexusClient({
  secretKey: process.env.NEXUS_SECRET_KEY || 'sk_dev_your_secret_key_here',
});

async function main() {
  const response = await nexus.workflows.trigger({
    workflowName: 'user.welcome',
    recipients: [
      {
        externalId: 'usr_active_99', // データベース内のサブスクライバーID
        email: 'alex@acme.io', // Email チャンネルに必要なフィールド
        phoneNumber: '+15550192834', // SMS/WhatsApp チャンネルに必要なフィールド
      },
    ],
    data: {
      name: 'Alex',
      companyName: 'Acme Corp',
    },
  });

  console.log('Trigger accepted status:', response.accepted); // true
}

main().catch(console.error);
```

サーバーでこのファイルを実行して、イベントトリガーを送信します。

</Step>

<Step>
### ログとサンドボックスの検証

API リクエストが成功すると、即座に **HTTP 202 Accepted** ペイロードが返されます。

- **監査ログ (Audit Logs)**: ダッシュボードで **Audit Logs** をクリックすると、ライブ実行トレースが表示されます。`Ingested` → `Queued` → `Compiled` → `Dispatched` のようなステップが確認できます。
- **サンドボックスシミュレーター**: **Development** 環境にいる間、送信メッセージ（Email、SMS）は外部プロバイダーの API 呼び出しを行いません。ダッシュボードの **Sandbox Simulator** にストリーミングされ、模擬メールやメッセージを無料で確認できます。

</Step>
</Steps>

## FAQ

<Accordions type="single">
  <Accordion title="開始するために10チャンネルすべてを構成する必要がありますか？">
    いいえ。メールやアプリ内ベルなど、単一のチャンネルから開始できます。ワークフロー内のチャンネルノードに対して資格情報が構成されていない場合、Nexus
    はそのステップを自動的にスキップします。
  </Accordion>
  <Accordion title="API が 200 OK ではなく 202 Accepted を返すのはなぜですか？">
    Nexus はイベント駆動型アーキテクチャで構築されています。API はイベントペイロードを BullMQ
    にエンキューし、10ms
    未満で応答してアプリケーションの高速性を維持します。その後、バックグラウンドワーカーがテンプレートのレンダリング、プロバイダーの検索、および通信事業者への発送を処理します。
  </Accordion>
  <Accordion title="Development 環境のトリガーは本物のメール/SMSを送信しますか？">
    デフォルトでは、**Development** 環境は **Sandbox Mode**
    で動作します。すべての送信はインターセプトされ、ダッシュボードの模擬受信トレイに表示されます。アプリ内通知は、リアルタイム
    WebSocket 経由でローカルアプリに配信されます。
  </Accordion>
  <Accordion title="API キーはどこにありますか？">
    API
    キーは環境ごとにスコープされています。ダッシュボードのトップバーのドロップダウンから環境を選択し、**Settings
    → API Keys**
    に移動します。シークレットキー（`sk_`）はサーバー側に保持し、パブリックキー（`pk_`）はフロントエンドで使用してください。
  </Accordion>
</Accordions>
