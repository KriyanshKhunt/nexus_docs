本番のユーザートラフィックを本番環境（Production）にルーティングする前に、このチェックリストを使用してください。各セクションを順番に進めてください。

---

## キーと環境

- [ ] 本番用のシークレットキー（`sk_prd_…`）がシークレットマネージャー（例: AWS Secrets Manager、Vault、 Railway secrets）に保存されていること — **絶対に Git にコミットしない**
- [ ] ステージング（Staging）環境で、`sk_stg_…` と実際のプロバイダー資格情報を使用してエンドツーエンドのテストを行っていること
- [ ] パブリックキー（`pk_prd_…`）がフロントエンドの環境変数にのみ保存されていること — バックエンドサービスには露出させない

---

## プロバイダー

- [ ] 必要なすべてのチャネルプロバイダーが本番（Production）環境下で接続されていること
- [ ] 各プロバイダーの **Test connection**（接続テスト）ボタンをパスしていること
- [ ] チャネルレイヤーごとに複数のプロバイダーを使用している場合、重み（比率）の割り当てが正しく構成されていること
- [ ] 正確な [コスト分析](/docs/platform/features/cost-analytics) のために、プロバイダーのユニットコストが入力されていること
- [ ] 月間予算の上限（バジェットキャップ）が構成され、警告送信用メールアドレスが確認されていること

---

## ワークフローとテンプレート

- [ ] すべてのテンプレートが **Production Active**（本番アクティブ）に昇格されていること（Draft や Archived ではない）
- [ ] 本番環境のすべてのワークフローが **Active**（アクティブ）に設定されていること
- [ ] フェイルオーバーチェーンがテストされていること — 重要なチャネルごとに少なくとも1つのセカンダリプロバイダーがあること
- [ ] ユーザー向けのマーケティングやダイジェスト配信用に、配信ウィンドウ（受け取り時間帯）が構成されていること
- [ ] トピックが適切なワークフローに割り当てられ、環境設定マトリクスがエンドツーエンドでテストされていること
- [ ] 該当する場合、キャンペーンでスマート送信時刻（Smart Send-Time）が有効になっていること

---

## SDK とバックエンド統合

- [ ] HMAC 署名がサブスクライバーセッションごとに **サーバー側** で生成されていること — ブラウザで計算しないこと
- [ ] サブスクライバーの `externalId` 値が、認証システムのユーザー ID と完全に一致していること
- [ ] Node SDK のエラー処理が実装されていること — `result.data` を使用する前に `result.ok` を確認する
- [ ] ネットワーク障害の際に再試行される可能性のあるトリガー呼び出しで、冪等性（idempotency）キーを使用していること
- [ ] 送信する前に、トリガーペイロードの `workflowName`、`recipients`、および `data` の形式が正しいことを検証していること

---

## コンプライアンスと運用

- [ ] GDPR 準拠のためのサブスクライバー削除プロセスがドキュメント化されていること — プロファイル、ログ、および Redis 状態の削除には `DELETE /v1/subscribers/:id` を使用する
- [ ] GDPR 準拠のデータエクスポートエンドポイントがテストされていること — `GET /v1/subscribers/:id/export` が完全なデータバンドルを返すこと
- [ ] チームの役割（Owner、Admin、Developer、Marketer）が割り当てられており、アカウントを共有していないこと
- [ ] すべての Owner および Admin アカウントで MFA（多要素認証）が有効になっていること
- [ ] 監査ログの保持期間およびオンコール（障害監視）の運用計画が定義されていること

---

## 請求

- [ ] サブスクリプションプランが、想定される月間トリガーボリュームと一致していること
- [ ] 上限超過時の動作（アラート付きのソフトキャップ、または強制停止）が確認されていること
- [ ] アカウント Owner 用に Stripe 請求ポータルへのアクセスが確認されていること

---

## 本番開始（Go-live）の手順

1. ダッシュボードの環境セレクターを **Production** に切り替えます。
2. 環境変数 `sk_prd_…` および `pk_prd_…` を使用してバックエンドをデプロイします。
3. まず内部チームメンバーのサブスクライバー宛てに、テスト用のカナリア（canary）トリガーを送信します。
4. 最初の1時間は、**Audit Logs** と **Overview** ダッシュボードを監視します。
5. カナリア制限を解除する前に、配信成功率が期待されるしきい値を超えていることを確認します。

<Callout type="warn">
  開発用のサンドボックス（Sandbox）モードは本番環境には**引き継がれません**。本番環境（Production）でのすべてのトリガーは、実際のプロバイダーを経由して送信され、通信費用が発生します。切り替える前に、ステージング（Staging）環境で十分にテストを行ってください。
</Callout>
