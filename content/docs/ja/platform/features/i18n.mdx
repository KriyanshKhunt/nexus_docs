Nexus は国際化（i18n）をネイティブにサポートしています。言語ごとに別々のワークフローを複製して作成する代わりに、ワークフローテンプレート内の各チャネルノード内にロケール固有のテキストコピーを直接保存できます。

---

## テンプレートの構造

ワークフローテンプレート定義において、`contentTemplates` オブジェクトにはチャネルキー（例: `email`、`sms`）が含まれます。チャネルがローカライズされている場合、その値はロケールコード（`en`、`es`、`ja`）をそれぞれのチャネルテンプレートにマッピングします。

### ローカライズされたコンテンツスキーマの例

```json
{
  "email": {
    "en": {
      "subject": "Your order has shipped!",
      "html": "<p>Hi {{ subscriber.first_name }}, your order is on its way.</p>"
    },
    "es": {
      "subject": "¡Tu pedido ha sido enviado!",
      "html": "<p>Hola {{ subscriber.first_name }}, tu pedido está en camino.</p>"
    }
  },
  "sms": {
    "en": {
      "body": "Hi {{ subscriber.first_name }}, your order has shipped."
    },
    "es": {
      "body": "Hola {{ subscriber.first_name }}, tu pedido ha sido enviado."
    }
  }
}
```

コンパイラーは、チャネルオブジェクトのキーが `LOCALE_KEY_REGEX = /^[a-z]{2,3}$/` に一致するかテストすることで、そのチャネルがローカライズされているかを判定します。一致する場合、解決されたロケールに対応するセグメントを抽出し、見つからない場合は英語（`en`）にフォールバックします。

---

## ロケール解決の優先順位

各配信において、Nexus は以下の優先順位でターゲット言語を決定します。

1. **トリガーによる上書き**: トリガーの `data` オブジェクトで渡される `_locale` プロパティ：
   ```ts
   data: {
     _locale: 'ja';
   }
   ```
2. **サブスクライバーの属性**: サブスクライバープロファイルの `locale` フィールド：
   ```ts
   recipients: [{ externalId: 'user_42', locale: 'ja-JP' }];
   ```
3. **環境のデフォルト値**: **`en`** にフォールバックします。

### バリデーションルール

- サブスクライバーのロケール文字列は、BCP 47 パターン（`/^[a-z]{2,3}(-[a-zA-Z0-9]{1,8})*$/`）を使用して検証されます。これにより、`en-US`、`es-MX`、`pt-BR` などの地域ロケールがサポートされます。
- `contentTemplates` のキーをマッチングする際、コンパイラーは地域のサフィックスを取り除きます（例: `ja-JP` は基本キーである `ja` に解決されます）。

## サポートされる基本ロケール

Nexus は、以下の基本言語に対するローカライズサポートを組み込みで提供しています。

| コード | 言語         | コード | 言語         |
| :----- | :----------- | :----- | :----------- |
| `en`   | 英語         | `nl`   | オランダ語   |
| `es`   | スペイン語   | `tr`   | トルコ語     |
| `fr`   | フランス語   | `hi`   | ヒンディー語 |
| `de`   | ドイツ語     | `ar`   | アラビア語   |
| `pt`   | ポルトガル語 | `ja`   | 日本語       |
| `it`   | イタリア語   | `zh`   | 中国語       |
| `ko`   | 韓国語       |        |              |

## 翻訳ファイルとローカライズテンプレートの使い分け

最適な管理を行うために、翻訳ファイルとローカライズテンプレートを組み合わせて使用してください。

- **ローカライズテンプレート**（本機能）は、チャネル固有の構造的なレイアウト、リッチメールコンテンツ、または言語間でのレイアウトの違いを定義するために使用します。
- **[翻訳ファイル](/docs/platform/features/translations)**は、複数のワークフローで参照される共有のキーと値のペアの文字列（フッター、ボタンのラベル、サポート用リンクなど）に対して `{{ t "key" }}` ヘルパーとともに使用します。
