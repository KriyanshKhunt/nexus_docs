description: カテゴリベースの通知環境設定 — 生のワークフロー名ではなく、「マーケティング」や「請求」といったグループ全体に対する購読・解除設定をユーザーに提供します。
---

**トピック（Topics）**は、通知のカテゴリを表現します（例: `"Billing"`、`"Product Updates"`、`"Marketing"` など）。バックエンドのシステム仕様に基づく生のイベント名（ワークフロー名）をユーザーに直接公開する代わりに、ワークフローを「トピック」に紐付けることで、ユーザーはトピック単位で配信設定を管理できます。

---

## トピックモデル

| フィールド      | 型     | 必須 | 説明                                                                                                                                                 |
| :-------------- | :----- | :--- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | string | ✅   | 一意のシステム識別キー（例: `billing_alerts`）。英小文字、数字、ダッシュ、アンダースコア（`^[a-z][a-z0-9_-]*$`、最大 64 文字）でなければなりません。 |
| `displayName`   | string | ✅   | 設定画面に表示されるユーザー向けの表示名（最大 128 文字）。                                                                                          |
| `description`   | string | —    | そのトピックがどのような内容を含むかについての簡単な説明（最大 256 文字）。                                                                          |
| `defaultStatus` | enum   | ✅   | 新規ユーザーの初期購読ステータス: `OPTED_IN`、`OPTED_OUT`、または `REQUIRED`。                                                                       |
| `sortOrder`     | number | —    | 設定画面テーブル内での行の表示順序を決定する整数値。                                                                                                 |

### 初期購読ステータスの詳細

- **`OPTED_IN`**: デフォルトで配信されますが、ユーザーが明示的に配信停止（オプトアウト）できます。
- **`OPTED_OUT`**: デフォルトでは配信されませんが、ユーザーが明示的に配信開始（オプトイン）できます。
- **`REQUIRED`**: 永久に配信されます。パスワードリセットや決済エラーなど、配信停止が許可されない極めて重要なアラートに使用します。

---

## 環境設定（購読設定）の評価フロー

ワークフローがトリガーされると：

1. Nexus は、実行されたワークフローが `topicId` に紐付けられているかを確認します。紐付けられていない場合、そのまま全チャネルステップが配信されます。
2. トピックに紐付けられている場合、エンジンは該当ユーザーの環境設定マトリクスから `topic:<name>` というキーを検索します。
3. チャネルに対して明示的な配信停止設定がある場合（例: `{ "topic:marketing": { "EMAIL": false } }`）、そのチャネルステップはスキップされ、履歴に `PREFERENCE_GATE` が記録されます。
4. 明示的なユーザー設定が存在しない場合、エンジンはトピックに設定されたデフォルト値（`defaultStatus`）にフォールバックして配信可否を決定します。

## SDK での使用方法

### アクティブなトピック一覧の取得

サブスクライバー側クライアントは、環境内に構成されているトピックのリストを取得して、カスタムの配信設定メニューをレンダリングできます：

```http
GET /v1/sdk/topics
x-nexus-public-key: pk_prd_…
```

**レスポンスボディ:**

```json
{
  "topics": [
    {
      "id": "topic-uuid",
      "name": "billing",
      "displayName": "Billing & Invoices",
      "defaultStatus": "REQUIRED"
    },
    {
      "id": "topic-uuid-2",
      "name": "marketing",
      "displayName": "Marketing & Promotions",
      "defaultStatus": "OPTED_OUT"
    }
  ]
}
```

このエンドポイントは、アクティブなチャネル情報とともに `GET /v1/sdk/notification-events` からも取得できます。

## React SDK コンポーネント

React SDK は、トピック別の配信設定を自動的に読み込み、グループ化し、更新するための、すぐに使えるUIコンポーネントを提供しています：

```tsx
import { PreferenceMatrix } from '@nexus-signal/react';

function UserSettings() {
  return (
    <div className="settings-panel">
      <h2>Notification Preferences</h2>
      <PreferenceMatrix />
    </div>
  );
}
```

このコンポーネントは、トピックを行としてレンダリングし、利用可能な各チャネル（Email、SMS、Push）を列としてレンダリングします。ユーザーがチェックボックスを切り替えると、クライアントは自動的にサブスクライバーの設定プロファイル（`PUT /v1/sdk/subscribers/:externalId/preferences`）を更新します。

## 制限事項

| 制限事項                   | 値       |
| :------------------------- | :------- |
| 環境あたりの最大トピック数 | 50       |
| システム識別キーの最大長さ | 64 文字  |
| 表示名の最大長さ           | 128 文字 |
