The **Nexus CLI** wraps the [Management API](/docs/api/management) to manage workflows, locales, and configurations from the terminal or within CI/CD pipelines.

## Installation

Install the package globally:

```bash
npm install -g @nexus-signal/cli
```

Or run commands on-the-fly without installing:

```bash
npx @nexus-signal/cli --help
```

---

## Authentication & Base Configuration

The CLI saves credentials locally to avoid requiring credentials on every command.

### Log in

Authenticate against a Nexus workspace. This saves your secret key to `~/.nexus-signal/config.json`.

```bash
nexus login
# Interactive prompt will request your sk_... key
```

To authenticate directly in a single command or script:

```bash
nexus login --key sk_prd_your_secret_key --url https://api.nexussignal.dev
```

### Display Identity

Verify connection status and key validity:

```bash
nexus whoami
```

### Log out

Delete cached credentials from your local system:

```bash
nexus logout
```

### Environment Overrides

Override stored credentials (ideal for CI/CD environments):

```bash
export NEXUS_SECRET_KEY=sk_prd_your_secret_key
export NEXUS_BASE_URL=https://api.nexussignal.dev
```

## Commands Reference

All commands support the `--json` flag to print parseable JSON directly to `stdout`.

### 1. Workflows

Create, download, and synchronize code-defined notification paths.

- **List workflows**:
  ```bash
  nexus workflows list
  ```
- **View workflow structure**:
  ```bash
  nexus workflows get order.shipped
  ```
- **Download definitions**: Saves remote workflows locally to `.nexus/workflows/*.json` files.
  ```bash
  nexus workflows pull --all
  nexus workflows pull --dir ./custom-workflows-path
  ```
- **Push definitions**: Upload local JSON definitions inside `.nexus/workflows/` back to the platform.
  ```bash
  nexus workflows push --all
  nexus workflows push --dir ./custom-workflows-path
  ```
- **Trigger workflow**: Run a workflow for specified recipient IDs.
  ```bash
  nexus workflows trigger order.shipped --to user_42,user_43 --data '{"orderId": "123"}' --tenant tenant_acme
  ```

---

### 2. Subscribers

Manage the recipients of your notification workflows.

- **List subscribers**: Search or filter recipients.
  ```bash
  nexus subscribers list --search alice --page 1 --limit 20
  ```
- **Get details**: Fetch subscriber profiles.
  ```bash
  nexus subscribers get user_42
  ```
- **Create / Update**: Upsert subscriber contact fields.
  ```bash
  nexus subscribers create --externalId user_42 --email billing@acme.io --phone +1234567890 --locale es --timezone America/New_York
  ```
- **Delete subscriber**: GDPR purge helper. Requires explicit confirmation.
  ```bash
  nexus subscribers delete user_42 --confirm
  ```

---

### 3. Objects & Subscriptions

Manage non-user entities (like projects, teams, or folders) for fan-out notifications.

- **List objects**: Fetch configured collections.
  ```bash
  nexus objects list
  nexus objects list --collection projects
  ```
- **Upsert object**: Set details for a non-user entity.
  ```bash
  nexus objects set --collection projects --id proj_alpha --name "Project Alpha" --properties '{"status": "active"}'
  ```
- **Subscribe recipients**: Subscribe users to watch an object. All subscribers are notified when this object is triggered.
  ```bash
  nexus objects subscribe --collection projects --id proj_alpha --subscribers user_42,user_43
  ```

---

### 4. B2B Tenants

Manage white-label isolation settings, preference matrices, and branding overrides for multi-tenant accounts.

- **List tenants**:
  ```bash
  nexus tenants list
  ```
- **Upsert tenant**: Create or edit multi-tenant settings.
  ```bash
  nexus tenants set --externalId tenant_acme --name "Acme Corp" --branding '{"logoUrl": "https://cdn.acme.io/logo.png", "primaryColor": "#2563eb"}'
  ```

---

### 5. Audiences

Group subscribers dynamically based on segmentation rules.

- **List audiences**: View segments.
  ```bash
  nexus audiences list
  ```
- **Create audience**: Create segments using filtering conditions.
  ```bash
  nexus audiences create --name "Inactive Users" --filters '[{"field": "globalUnsubscribed", "operator": "is_false"}]' --description "Non-unsubscribed subscribers"
  ```

---

### 6. Broadcasts

Schedule or send one-time notification workflows to audiences.

- **List broadcasts**: View status and recipient count.
  ```bash
  nexus broadcasts list
  ```
- **Create broadcast**: Stage a workflow send to an audience.
  ```bash
  nexus broadcasts create --name "Q3 Update" --workflowId <workflow-uuid> --audienceId <audience-uuid> --scheduledAt "2026-10-01T12:00:00Z"
  ```
- **Trigger broadcast**: Send a created broadcast immediately.
  ```bash
  nexus broadcasts send <broadcast-uuid>
  ```

---

### 7. In-Product Guides

Query eligible banners, badges, and modal definitions.

- **List guides**: Check configured in-app guides.
  ```bash
  nexus guides list
  ```
- **Get details**: Fetch guide configuration JSON.
  ```bash
  nexus guides get <guide-uuid>
  ```

---

### 8. Email Layouts

Manage email HTML wrapper templates programmatically.

- **List layouts**: List available wrapper layouts.
  ```bash
  nexus layouts list
  ```
- **Push layout**: Upload an email wrapper template (requires the `{{{content}}}` placeholder).
  ```bash
  nexus layouts push --name transactional-layout --file ./templates/layout.html --default
  ```

---

### 9. Translations (i18n)

Manage localized dictionary bundles for email layouts.

- **List translation bundles**:
  ```bash
  nexus translations list
  ```
- **Download translation files**: Pulls remote BCP 47 translations locally to `.nexus/translations/` files.
  ```bash
  nexus translations pull --dir ./custom-locales-path
  ```
- **Upload translation file**: Pushes a local key-value JSON file for a locale.
  ```bash
  nexus translations push --locale es --file ./locales/es.json --namespace billing
  ```

---

### 10. Utility & schedules

Verify connections, perform diagnostic health runs, check execution logs, and track schedules.

- **Check connectivity**: Perform ping diagnostics.
  ```bash
  nexus health
  ```
- **Quick Send**: Direct workflow send to a single recipient shortcut.
  ```bash
  nexus send order.shipped --to user_42 --data '{"orderId": "123"}' --tenant tenant_acme
  ```
- **Inspect logs**: Lookup status of an execution log ID.
  ```bash
  nexus logs <logId>
  ```
- **List schedules**: View active recurring cron workflows.
  ```bash
  nexus schedules list
  ```

## Piping & Scripting

The `--json` output format makes it easy to integrate the CLI with scripting utilities like `jq` and `xargs`:

```bash
# List all workflow names
nexus workflows list --json | jq -r '.[].name'

# Extract failed recipient delivery states
nexus logs <logId> --json | jq '.deliverySteps[].error'
```

If a command succeeds, the CLI exits with code `0`. If it fails, the CLI exits with code `1`.

## CI/CD Workflow Integration

You can integrate the CLI into your GitHub Actions pipelines for automated deploys:

```yaml
name: Deploy Notifications

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Deploy Nexus Workflows
        run: npx @nexus-signal/cli workflows push --all
        env:
          NEXUS_SECRET_KEY: ${{ secrets.NEXUS_SECRET_KEY }}
          NEXUS_BASE_URL: https://api.nexussignal.dev
```
