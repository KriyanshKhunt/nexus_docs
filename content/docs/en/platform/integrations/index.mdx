Nexus acts as a routing controller that sits in front of **your own provider accounts**. Configure API credentials once in the dashboard **Integrations** hub, and Nexus handles routing, failover, templates, and delivery tracking.

---

## Integration layers & providers

| Layer        | Key                                | Supported providers                             | Description                            |
| :----------- | :--------------------------------- | :---------------------------------------------- | :------------------------------------- |
| **Email**    | `email`                            | SendGrid, Resend, Amazon SES, Postmark, Mailgun | Transactional and marketing emails     |
| **SMS**      | `sms`                              | Twilio, Vonage, Plivo, Sinch                    | Fast SMS alerts and OTPs               |
| **WhatsApp** | `whatsapp`                         | Meta Cloud API, Twilio WhatsApp, Infobip        | Rich B2C chat communications           |
| **Push**     | `push`                             | Firebase Cloud Messaging (FCM), Apple APNs      | Web and mobile push notifications      |
| **Chat**     | `slack` \| `discord` \| `ms_teams` | Slack, Discord, Microsoft Teams                 | Direct chat workspace updates          |
| **Webhooks** | `webhook`                          | Custom HTTP fetch targets                       | Direct backend-to-backend webhooks     |
| **AI**       | `openai_ai` \| `anthropic_ai`      | OpenAI, Anthropic                               | Content generation & runtime LLM nodes |

## Weight configuration (A/B Routing)

If you configure multiple integrations for a single layer, you can divide traffic between them by setting custom weights:

```http
PUT /v1/integrations/weights/email
Authorization: Bearer <jwt_dashboard_token>
Content-Type: application/json

{
  "weights": {
    "sendgrid": 70,
    "resend": 30
  }
}
```

- **Supported layers**: `email`, `sms`, `whatsapp`, `push`, `webhook`, `slack`, `discord`, `ms_teams`.
- **Validation**: All weights inside a layer must sum to exactly **100**.

## Security

All provider API keys, tokens, and client secrets are encrypted on the server side using AES-256-GCM before writing to the database. Decryption occurs only at the memory level in the worker threads when dispatching outbound deliveries.
