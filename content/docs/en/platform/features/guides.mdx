---
title: In-Product Guides
description: Targeted banners, modals, cards, and tooltips managed from the dashboard — not workflow-triggered notifications.
---

**Guides** deliver in-product UI surfaces controlled entirely from the dashboard. Engineers integrate the SDK hook once; product managers control content, targeting, scheduling, and activation without code changes.

## Guide types

| Type      | Best for                                            |
| :-------- | :-------------------------------------------------- |
| `BANNER`  | Top-of-page announcements, maintenance notices      |
| `MODAL`   | Feature launches, upgrade prompts, onboarding flows |
| `CARD`    | Inline feature callouts and contextual tips         |
| `TOOLTIP` | Contextual hints anchored to specific UI elements   |

## Guide content schema

Each guide has a structured content object:

| Field          | Type                                                     | Description                                       |
| :------------- | :------------------------------------------------------- | :------------------------------------------------ |
| `title`        | string                                                   | Headline text (max 256 characters)                |
| `body`         | string                                                   | Main body text (max 5,000 characters)             |
| `cta`          | `{ label, url, action }`                                 | Primary call-to-action button                     |
| `secondaryCta` | `{ label, url }`                                         | Secondary button (e.g., "Maybe later")            |
| `media`        | `{ url, alt }`                                           | Optional image                                    |
| `dismissible`  | boolean                                                  | Whether user can close the guide (default `true`) |
| `theme`        | `info` \| `success` \| `warning` \| `error` \| `neutral` | Visual style variant                              |

## Targeting

Guides can target subscribers based on:

- **Audience**: Link to an existing [Audience](/docs/platform/features/audiences) segment
- **Custom rules**: Additional `rules` array filtered on subscriber fields (same format as audiences)
- **Logic**: `AND` / `OR` across rules

## Activation

Control _when and where_ a guide appears using the `activation` object:

| Field        | Options                                           | Description                                                    |
| :----------- | :------------------------------------------------ | :------------------------------------------------------------- |
| `urlPattern` | string                                            | Page URL pattern to match                                      |
| `pageMatch`  | `exact` \| `starts_with` \| `contains` \| `regex` | How to match the URL (default: `starts_with`)                  |
| `frequency`  | `once` \| `once_per_session` \| `always`          | How often to show the guide per user                           |
| `delay`      | number (ms)                                       | Milliseconds to wait after page load before showing (0–60,000) |

## Priority & scheduling

- **Priority** (0–100): Higher priority guides surface first when multiple guides match the same user/page
- **startAt / endAt**: Optional ISO 8601 datetime — guides are only active within this window

## SDK integration

Guides are fetched client-side via a polling/on-demand API call, not pushed via WebSocket.

<Tabs items={['React', 'Headless JS']}>
  <Tab value="React">

```tsx
import { useGuides } from '@nexus-signal/react';

function GuideRenderer() {
  const { guides, markSeen, markInteracted, dismiss } = useGuides({
    pathname: window.location.pathname,
  });

  return guides.map((guide) => (
    <div key={guide.id}>
      <h3>{guide.content.title}</h3>
      <p>{guide.content.body}</p>
      {guide.content.cta && (
        <a href={guide.content.cta.url} onClick={() => markInteracted(guide.id)}>
          {guide.content.cta.label}
        </a>
      )}
      {guide.content.dismissible && <button onClick={() => dismiss(guide.id)}>Dismiss</button>}
    </div>
  ));
}
```

```ts
// Fetch guides for the current page context
await nexus.guides.fetch({ pathname: '/dashboard' });

// Mark that the user saw the guide
nexus.guides.markSeen(guideId);

// Mark that the user interacted (clicked CTA)
nexus.guides.markInteracted(guideId);

// Dismiss the guide permanently
nexus.guides.dismiss(guideId);
```

**SDK route**: `GET /v1/sdk/guides?pathname=/dashboard` — returns active, matching guides for the authenticated subscriber.

## Guide lifecycle events

| Event        | SDK method           | Meaning                                       |
| :----------- | :------------------- | :-------------------------------------------- |
| `seen`       | `markSeen(id)`       | User saw (scrolled past / rendered) the guide |
| `interacted` | `markInteracted(id)` | User clicked the primary CTA                  |
| `archived`   | `dismiss(id)`        | User explicitly dismissed the guide           |

Events are posted to `POST /v1/sdk/guides/:guideId/events` and feed into analytics.

## Guide statuses

| Status     | Meaning                                                           |
| :--------- | :---------------------------------------------------------------- |
| `DRAFT`    | Not visible to users                                              |
| `ACTIVE`   | Served to matching users (up to 20 active guides per environment) |
| `PAUSED`   | Temporarily hidden without deletion                               |
| `ARCHIVED` | Permanently retired                                               |

## Limits

| Limit                             | Value |
| :-------------------------------- | :---- |
| Max guides per environment        | 50    |
| Max active guides per environment | 20    |
| Max targeting rules per guide     | 10    |
