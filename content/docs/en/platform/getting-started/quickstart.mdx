# Quickstart

This guide walks you through sending your first notification event and checking the real-time delivery logs.

### Create a Workspace & Retrieve Keys [step]

Log in to the [Nexus Dashboard](https://app.nexussignal.dev). Your workspace comes pre-configured with **three fully isolated environments**:

| Environment     | Key Prefix            | Purpose                                               |
| --------------- | --------------------- | ----------------------------------------------------- |
| **Development** | `pk_dev_` / `sk_dev_` | Local staging, developer sandbox, and mock testing.   |
| **Staging**     | `pk_stg_` / `sk_stg_` | Internal testing, QA pipelines, and staging branches. |
| **Production**  | `pk_prd_` / `sk_prd_` | Production traffic and live user notifications.       |

Navigate to **Settings → API Keys** to copy the keys for your current active environment.

### Design Your First Workflow [step]

1. Go to the **Workflows** page in the dashboard.
2. Click **Create Workflow** and name the event trigger: `user.welcome`.
3. In the visual canvas, drag and drop an **Email Channel Node** right below the primary trigger.
4. Click the Email node to configure its subject line (e.g., `Welcome to Acme, {{ data.name }}!`) and standard template layout.
5. Click **Publish** to deploy the workflow template to your active environment.

### Connect a Delivery Provider (BYOP) [step]

Nexus requires a delivery gateway to dispatch notifications.

1. Go to the **Integrations** tab in the dashboard.
2. Select your provider of choice (e.g., **SendGrid**, **Resend**, or **Twilio**).
3. Enter your provider API credentials. Your credentials are fully encrypted at rest using AES-256 and decrypted only at the moment of execution.

### Trigger the Event [step]

Create a script on your backend server to initialize the client and trigger the `user.welcome` workflow:

```ts title="trigger.ts"
import { NexusClient } from '@nexus-signal/node';

// Initialize client with secret key (Server-only)
const nexus = new NexusClient({
  secretKey: process.env.NEXUS_SECRET_KEY || 'sk_dev_your_secret_key_here',
});

async function main() {
  const response = await nexus.workflows.trigger({
    workflowName: 'user.welcome',
    recipients: [
      {
        externalId: 'usr_active_99', // The subscriber ID in your database
        email: 'alex@acme.io', // Required for Email channels
        phoneNumber: '+15550192834', // Required for SMS/WhatsApp channels
      },
    ],
    data: {
      name: 'Alex',
      companyName: 'Acme Corp',
    },
  });

  console.log('Trigger accepted status:', response.accepted); // true
}

main().catch(console.error);
```

Run this file on your server to emit the event trigger.

### Verify Logs & Sandbox [step]

A successful API request returns an **HTTP 202 Accepted** payload immediately.

- **Audit Logs**: In the dashboard, click **Audit Logs** to view the live execution trace. You will see steps like `Ingested` → `Queued` → `Compiled` → `Dispatched`.
- **Sandbox Simulator**: While in the **Development** environment, outbound messages (Email, SMS) do not make external provider API calls. They stream to the dashboard **Sandbox Simulator** so you can view mock emails and messages for free.

## FAQ

<Accordions type="single">
  <Accordion title="Do I need to configure all 10 channels to get started?">
    No. You can start with a single channel (like Email or In-App). Nexus will skip any node channel
    inside a workflow if no credentials are configured for it.
  </Accordion>
  <Accordion title="Why does the API return 202 Accepted instead of 200 OK?">
    Nexus is built on an event-driven architecture. The API enqueues the event payload to BullMQ and
    responds in under 10ms to keep your application fast, while background workers handle templates,
    provider lookups, and carrier dispatches.
  </Accordion>
  <Accordion title="Do Development API triggers send real emails/SMS?">
    By default, the **Development** environment operates in **Sandbox Mode**. All outbound
    dispatches are intercepted and shown in the dashboard's simulated inbox. In-App notifications
    are still delivered via real-time WebSockets to your local app.
  </Accordion>
  <Accordion title="Where do I locate my API keys?">
    API keys are scoped per environment. Select your environment from the top-bar dropdown in the
    dashboard, then go to **Settings → API Keys**. Keep secret keys (`sk_`) on your server and
    public keys (`pk_`) on the frontend.
  </Accordion>
</Accordions>
