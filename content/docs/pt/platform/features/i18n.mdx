# Modelos Multilíngues

O Nexus inclui suporte nativo para internacionalização (i18n). Em vez de duplicar workflows para diferentes idiomas, você armazena o texto específico de cada localidade diretamente dentro de cada nó de canal no modelo do workflow.

---

## Estrutura do Modelo

Na definição do modelo de workflow, o objeto `contentTemplates` contém chaves de canais (por exemplo, `email`, `sms`). Se um canal for localizado, seu valor mapeia códigos de localidades (`en`, `es`, `pt`, `ja`) aos seus respectivos modelos de canal.

### Exemplo de Esquema de Conteúdo Localizado

```json
{
  "email": {
    "en": {
      "subject": "Your order has shipped!",
      "html": "<p>Hi {{ subscriber.first_name }}, your order is on its way.</p>"
    },
    "es": {
      "subject": "¡Tu pedido ha sido enviado!",
      "html": "<p>Hola {{ subscriber.first_name }}, tu pedido está en camino.</p>"
    }
  },
  "sms": {
    "en": {
      "body": "Hi {{ subscriber.first_name }}, your order has shipped."
    },
    "es": {
      "body": "Hola {{ subscriber.first_name }}, tu pedido ha sido enviado."
    }
  }
}
```

O compilador verifica se o objeto do canal é localizado testando suas chaves com a regex `LOCALE_KEY_REGEX = /^[a-z]{2,3}$/`. Se houver correspondência, ele extrai o segmento correspondente à localidade resolvida, fazendo fallback para o inglês (`en`) caso não encontre uma correspondência.

---

## Cadeia de Resolução de Localidade

Para cada entrega, o Nexus determina o idioma de destino nesta ordem de prioridade estrita:

1. **Substituição por disparo**: A propriedade `_locale` passada no objeto `data` do gatilho:
   ```ts
   data: {
     _locale: 'es';
   }
   ```
2. **Propriedade do inscrito**: O campo `locale` no perfil do inscrito:
   ```ts
   recipients: [{ externalId: 'user_42', locale: 'es-MX' }];
   ```
3. **Padrão do ambiente**: Faz fallback para o inglês **`en`**.

### Regras de Validação

- As strings de localidade do inscrito são validadas usando o padrão BCP 47 (`/^[a-z]{2,3}(-[a-zA-Z0-9]{1,8})*$/`). Isso permite localidades regionais como `en-US`, `es-MX` e `pt-BR`.
- Ao corresponder as chaves no objeto `contentTemplates`, o compilador remove os sufixos regionais (por exemplo, `es-MX` resolve para a chave base `es`).

## Localidades Base Suportadas

O Nexus possui suporte de localização integrado para as seguintes localidades base:

| Código | Idioma    | Código | Idioma                |
| :----- | :-------- | :----- | :-------------------- |
| `en`   | Inglês    | `nl`   | Holandês (Nederlands) |
| `es`   | Espanhol  | `tr`   | Turco                 |
| `fr`   | Francês   | `hi`   | Hindi                 |
| `de`   | Alemão    | `ar`   | Árabe                 |
| `pt`   | Português | `ja`   | Japonês               |
| `it`   | Italiano  | `zh`   | Chinês                |
| `ko`   | Coreano   |        |                       |

## Arquivos de Tradução vs Modelos Localizados

Para uma organização ideal, combine arquivos de tradução e modelos localizados:

- **Use modelos localizados** (este recurso) para layouts estruturais específicos de canais, e-mails com conteúdo rico em HTML ou quando houver diferenças de layouts estruturais entre os idiomas.
- **Use [Arquivos de Tradução](/docs/platform/features/translations)** com o helper `{{ t "key" }}` para strings simples de chave-valor compartilhadas (por exemplo, rodapés, rótulos de botões, links de suporte) referenciadas em múltiplos workflows.
