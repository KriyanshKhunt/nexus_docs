# Tópicos de Notificação

Os **Tópicos** representam categorias de notificações (por exemplo, `"Billing"`, `"Product Updates"`, `"Marketing"`). Em vez de expor nomes de eventos de workflows brutos de backend aos inscritos, você associa os workflows a um tópico. Os inscritos gerenciam suas preferências no nível do tópico.

---

## Modelo de Tópico

| Campo           | Tipo   | Obrigatório | Descrição                                                                                                                                                                       |
| :-------------- | :----- | :---------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`          | string | ✅          | Identificador de máquina exclusivo (por exemplo, `billing_alerts`). Deve ser alfanumérico em letras minúsculas com hífen/sublinhado (`^[a-z][a-z0-9_-]*$`, máx. 64 caracteres). |
| `displayName`   | string | ✅          | Nome de exibição voltado ao usuário no menu de preferências (máx. 128 caracteres).                                                                                              |
| `description`   | string | —           | Breve resumo voltado ao usuário descrevendo o conteúdo deste tópico (máx. 256 caracteres).                                                                                      |
| `defaultStatus` | enum   | ✅          | Estado inicial de assinatura para novos inscritos: `OPTED_IN`, `OPTED_OUT` ou `REQUIRED`.                                                                                       |
| `sortOrder`     | number | —           | Número inteiro que define a ordem de exibição das linhas nas tabelas de preferências.                                                                                           |

### Explicação dos Status Padrão

- **`OPTED_IN`**: Os inscritos são inscritos por padrão, mas podem optar explicitamente por sair.
- **`OPTED_OUT`**: Os inscritos não são inscritos por padrão, mas podem optar explicitamente por entrar.
- **`REQUIRED`**: Os inscritos são permanentemente inscritos. Representa alertas críticos (por exemplo, redefinições de senha, avisos de falha de faturamento) que não podem ser desativados.

---

## Como as Preferências são Avaliadas

Quando um workflow é disparado:

1. O Nexus verifica se o workflow está associado a um `topicId`. Se não estiver, ele executa as etapas do canal normalmente.
2. Se estiver associado, o motor de execução verifica a matriz de preferências do inscrito para chaves estruturadas como `topic:<name>`.
3. Se existir uma preferência explícita definida para o canal (por exemplo, `{ "topic:marketing": { "EMAIL": false } }`), a etapa é ignorada, registrando `PREFERENCE_GATE` no ciclo de vida.
4. Se nenhuma preferência explícita estiver definida, o motor de execução adota a configuração `defaultStatus` configurada no tópico.

## Integração com o SDK

### Buscar Tópicos Ativos

O cliente do inscrito pode buscar a lista de tópicos configurados no ambiente para renderizar menus personalizados:

```http
GET /v1/sdk/topics
x-nexus-public-key: pk_prd_…
```

**Corpo da resposta:**

```json
{
  "topics": [
    {
      "id": "topic-uuid",
      "name": "billing",
      "displayName": "Billing & Invoices",
      "defaultStatus": "REQUIRED"
    },
    {
      "id": "topic-uuid-2",
      "name": "marketing",
      "displayName": "Marketing & Promotions",
      "defaultStatus": "OPTED_OUT"
    }
  ]
}
```

Este endpoint também é incluído em `GET /v1/sdk/notification-events` juntamente com os canais ativos.

## Componentes do React SDK

O React SDK fornece um componente pronto para uso que carrega, agrupa e atualiza automaticamente as preferências por tópico:

```tsx
import { PreferenceMatrix } from '@nexus-signal/react';

function UserSettings() {
  return (
    <div className="settings-panel">
      <h2>Notification Preferences</h2>
      <PreferenceMatrix />
    </div>
  );
}
```

O componente renderiza os tópicos como linhas e os canais disponíveis (Email, SMS, Push) como colunas. Quando um usuário alterna uma caixa de seleção, o cliente atualiza o perfil do inscrito (`PUT /v1/sdk/subscribers/:externalId/preferences`) de forma automática.

## Limites

| Limite                                 | Valor          |
| :------------------------------------- | :------------- |
| Máximo de tópicos por ambiente         | 50             |
| Comprimento máximo do nome de máquina  | 64 caracteres  |
| Comprimento máximo do nome de exibição | 128 caracteres |
