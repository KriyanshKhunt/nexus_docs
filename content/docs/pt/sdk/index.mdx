## Fluxo de Arquitetura Integrada

O diagrama a seguir rastreia os limites das transações entre os envios do lado do servidor, sockets de agentes de usuários e retransmissões de provedores externos:

```mermaid
flowchart TD
  subgraph Server Environment [Entorno do Servidor]
    App(Seu Servidor de App) -->|1. Inicializar SDK com sk_*| SDK(SDK Node.js)
    SDK -->|2. Disparar Workflow| API(API REST do Nexus)
    SDK -->|3. Gerar HMAC| App
  end

  subgraph Client Environment [Entorno do Cliente]
    App -->|4. Passar subscriberId + HMAC| FE(App no Navegador)
    FE -->|5. Conectar WebSocket com pk_*| WebHost(Gateway Socket.IO)
  end

  subgraph Background Processing [Processamento em Segundo Plano]
    API -->|6. Enfileirar Job| Q[(Fila do Redis)]
    Q -->|7. Processamento de Workers| Workers(Workers Assíncronos)
    Workers -->|8. Enviar Evento ao Vivo| WebHost
    Workers -->|9. Despachar Chamada à Operadora| Carriers("Provedores (Twilio/SendGrid)")
  end

  WebHost -->|10. Transmitir para o Feed| FE
```

## Matriz de Suporte de Pacotes

Certifique-se de que seus ambientes de execução atendam aos requisitos mínimos:

| Namespace do Pacote            | Ambiente de Execução | Dependências de Parceria    | Responsabilidade Principal                                                          |
| :----------------------------- | :------------------- | :-------------------------- | :---------------------------------------------------------------------------------- |
| **`@nexus-signal/node`**       | Node.js >= 18.0.0    | Nenhuma (Fetch Nativo)      | Gatilhos de backend, schedules, sincronização de objetos e de workflows.            |
| **`@nexus-signal/react`**      | React >= 18.0.0      | `socket.io-client >= 4.8.0` | Sinos pré-estilizados, feeds de página inteira, preferências.                       |
| **`@nexus-signal/js`**         | ES6 / HTML5          | `socket.io-client >= 4.8.0` | Handlers de armazenamento agnósticos de framework, emissores WebSocket.             |
| **`@nexus-signal/angular`**    | Angular >= 17.0.0    | `socket.io-client >= 4.8.0` | Signals reativos, wrappers de componentes independentes.                            |
| **`@nexus-signal/cli`**        | Node.js >= 18.0.0    | Nenhuma                     | Sincronização de esquemas locais, pipelines de promoção de CI/CD.                   |
| **`@nexus-signal/mcp-server`** | Node.js >= 18.0.0    | Nenhuma                     | Chamadas de ferramentas em linguagem natural para assistentes de codificação de IA. |

## Instalação Rápida

Configure as bibliotecas dependendo dos pontos de entrada em sua aplicação:

<Tabs items={['Server-side', 'React Client', 'Dev Tooling']}>
  <Tab value="Server-side">
    Para executar gatilhos e sincronizar workflows a partir das rotas do seu backend:
    ```bash
    npm install @nexus-signal/node
    ```
  </Tab>
  <Tab value="React Client">
    Para montar centros de notificação in-app e configurações de usuário dentro de uma árvore React:
    ```bash
    npm install @nexus-signal/react socket.io-client
    ```
  </Tab>
  <Tab value="Dev Tooling">
    Para acessar mecanismos de sincronização local ou iniciar uma instância do MCP:
    ```bash
    # Instalar a CLI globalmente
    npm install -g @nexus-signal/cli

    # Executar o servidor MCP imediatamente
    npx -y @nexus-signal/mcp-server@latest
    ```

  </Tab>
</Tabs>

<Callout type="warn">
  **Regra de Exposição de Chaves**: Nunca incorpore chaves secretas que começam com `sk_` em código
  do lado do cliente, Single Page Apps (SPAs) ou scripts compilados. As rotas públicas devem sempre
  utilizar chaves públicas (`pk_`) verificadas em relação a uma assinatura HMAC gerada estritamente
  no seu servidor.
</Callout>
