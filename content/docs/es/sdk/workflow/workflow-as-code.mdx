Define workflows de notificación junto con el código de tu aplicación, luego sincronízalos con Nexus con un solo comando o llamada API.

## Por qué workflow-as-code

| Solo panel                                  | Workflow-as-code                                       |
| ------------------------------------------- | ------------------------------------------------------ |
| Ediciones manuales en el lienzo             | Definiciones en TypeScript rastreadas por Git          |
| Difícil de revisar en PRs                   | Compara los cambios de workflows como cualquier código |
| Sin comprobaciones en tiempo de compilación | Autocompletado de IDE en tipos de pasos                |

## Definir un workflow

```ts
import { defineWorkflow } from '@nexus-signal/node';

export const orderShipped = defineWorkflow('order.shipped', {
  description: 'Notify when an order ships',
  tags: ['orders', 'transactional'],
  active: true,
})
  .addChannel('IN_APP')
  .addChannel('EMAIL', { suppressWhenOnline: true })
  .addDelay({ hours: 2 })
  .addChannel('SMS', {
    conditions: {
      logic: 'AND',
      rules: [{ variable: 'data.priority', operator: 'equals', value: 'high' }],
    },
  })
  .toDefinition();
```

## Sincronizar con la plataforma

```ts
import { NexusClient } from '@nexus-signal/node';
import { orderShipped } from './workflows/order-shipped';

const nexus = new NexusClient({ secretKey: process.env.NEXUS_SECRET_KEY! });

const result = await nexus.workflows.sync(orderShipped);
// o sincronizar múltiples: await nexus.workflows.sync([orderShipped, welcomeEmail]);
```

Equivalente en HTTP:

```http
POST /v1/workflows/sync
Authorization: Bearer sk_prd_…
```

## Constructores de pasos disponibles

| Método                                       | Mapeo al nodo del lienzo         |
| -------------------------------------------- | -------------------------------- |
| `addChannel(kind, opts?)`                    | Canal (EMAIL, SMS, IN_APP, etc.) |
| `addDelay({ hours, minutes })`               | Delay                            |
| `addDigest({ windowMinutes })`               | Digest                           |
| `addThrottle({ maxCount, windowSeconds })`   | Throttle                         |
| `addHttpFetch({ url, method, responseKey })` | HTTP Fetch                       |
| `addAiNode({ prompt, responseKey })`         | AI Node                          |

Todos los métodos de pasos aceptan `conditions` opcionales — ver [Condiciones de paso](/docs/platform/features/step-conditions).

## Ejemplo avanzado

```ts
export const escalation = defineWorkflow('payment.overdue')
  .addHttpFetch({
    url: 'https://api.billing.com/invoices/{{ data.invoiceId }}',
    method: 'GET',
    responseKey: 'invoice',
  })
  .addAiNode({
    prompt:
      'Classify urgency for invoice {{ data.invoice.amount }} due {{ data.invoice.dueDate }}. Return: low, medium, or high.',
    responseKey: 'urgency',
  })
  .addChannel('EMAIL')
  .addChannel('SMS', {
    conditions: {
      logic: 'OR',
      rules: [{ variable: 'data.urgency', operator: 'equals', value: 'high' }],
    },
  })
  .toDefinition();
```

## Sincronización de CLI

```bash
nexus workflows sync --file ./workflows/order-shipped.json
# o subir archivos JSON desde .nexus/workflows/
nexus workflows push --all
```

## Sincronización de MCP

Los agentes de IA pueden subir definiciones a través de la herramienta `nexus_sync_workflows` — ver [Servidor MCP](/docs/sdk/devtools/mcp-server).
