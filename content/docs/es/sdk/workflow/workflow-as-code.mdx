Define flujos de trabajo de notificación junto con el código de tu aplicación, luego sincronízalos con Nexus con un solo comando o llamada API.

## Por qué utilizar flujos de trabajo como código

| Solo desde el panel (Dashboard)             | Flujo de trabajo como código                               |
| ------------------------------------------- | ---------------------------------------------------------- |
| Ediciones manuales en el lienzo             | Definiciones en TypeScript rastreadas con Git              |
| Difícil de revisar en Pull Requests (PR)    | Compara cambios en flujos de trabajo como cualquier código |
| Sin comprobaciones en tiempo de compilación | Autocompletado del IDE en tipos de pasos                   |

## Definir un workflow

```ts
import { defineWorkflow } from "@nexus-signal/node";

export const orderShipped = defineWorkflow("order.shipped", {
  description: "Notify when an order ships",
  tags: ["orders", "transactional"],
  active: true,
})
  .addChannel("IN_APP")
  .addChannel("EMAIL", { suppressWhenOnline: true })
  .addDelay({ hours: 2 })
  .addChannel("SMS", {
    conditions: {
      logic: "AND",
      rules: [{ variable: "data.priority", operator: "equals", value: "high" }],
    },
  })
  .toDefinition();
```

## Sincronizar con la plataforma

```ts
import { NexusClient } from "@nexus-signal/node";
import { orderShipped } from "./workflows/order-shipped";

const nexus = new NexusClient({ secretKey: process.env.NEXUS_SECRET_KEY! });

const result = await nexus.workflows.sync(orderShipped);
// o sincronizar múltiples: await nexus.workflows.sync([orderShipped, welcomeEmail]);
```

Equivalente en HTTP:

```http
POST /v1/workflows/sync
Authorization: Bearer sk_prd_…
```

## Constructores de pasos disponibles

| Método                                       | Mapeo en el nodo del lienzo      |
| -------------------------------------------- | -------------------------------- |
| `addChannel(kind, opts?)`                    | Canal (EMAIL, SMS, IN_APP, etc.) |
| `addDelay({ hours, minutes })`               | Delay (Retraso)                  |
| `addDigest({ windowMinutes })`               | Digest (Resumen)                 |
| `addThrottle({ maxCount, windowSeconds })`   | Throttle (Limitador)             |
| `addHttpFetch({ url, method, responseKey })` | HTTP Fetch (Petición HTTP)       |
| `addAiNode({ prompt, responseKey })`         | AI Node (Nodo de IA)             |

Todos los métodos de pasos aceptan `conditions` opcionales — ver [Condiciones de Paso](/docs/platform/features/step-conditions).

## Ejemplo avanzado

```ts
export const escalation = defineWorkflow("payment.overdue")
  .addHttpFetch({
    url: "https://api.billing.com/invoices/{{ data.invoiceId }}",
    method: "GET",
    responseKey: "invoice",
  })
  .addAiNode({
    prompt:
      "Classify urgency for invoice {{ invoice.amount }} due {{ invoice.dueDate }}. Return: low, medium, or high.",
    responseKey: "urgency",
  })
  .addChannel("EMAIL")
  .addChannel("SMS", {
    conditions: {
      logic: "OR",
      rules: [{ variable: "data.urgency", operator: "equals", value: "high" }],
    },
  })
  .toDefinition();
```

## Sincronización desde la CLI

```bash
nexus workflows sync --file ./workflows/order-shipped.json
# o subir archivos JSON desde .nexus/workflows/
nexus workflows push --all
```

## Sincronización desde MCP

Los agentes de IA pueden subir definiciones a través de la herramienta `nexus_sync_workflows` — ver [Servidor MCP de IA](/docs/sdk/devtools/mcp-server).
