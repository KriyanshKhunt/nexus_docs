---
title: Plantillas Multi-Idioma
description: Plantillas de mensajes localizadas — ejecuta un único workflow y entrega el copy automáticamente en el idioma del suscriptor.
---

Nexus incluye soporte nativo para la internacionalización (i18n). En lugar de duplicar workflows para diferentes idiomas, almacenas el copy específico del locale directamente dentro de cada nodo de canal en la plantilla del workflow.

---

## Estructura de la plantilla

En la definición de la plantilla del workflow, el objeto `contentTemplates` contiene claves de canal (por ejemplo, `email`, `sms`). Si un canal está localizado, su valor mapea códigos de locale (`en`, `es`, `ja`) a sus respectivas plantillas de canal.

### Ejemplo de esquema de contenido localizado

```json
{
  "email": {
    "en": {
      "subject": "Your order has shipped!",
      "html": "<p>Hi {{ subscriber.first_name }}, your order is on its way.</p>"
    },
    "es": {
      "subject": "¡Tu pedido ha sido enviado!",
      "html": "<p>Hola {{ subscriber.first_name }}, tu pedido está en camino.</p>"
    }
  },
  "sms": {
    "en": {
      "body": "Hi {{ subscriber.first_name }}, your order has shipped."
    },
    "es": {
      "body": "Hola {{ subscriber.first_name }}, tu pedido ha sido enviado."
    }
  }
}
```

El compilador comprueba si el objeto del canal está localizado probando sus claves con `LOCALE_KEY_REGEX = /^[a-z]{2,3}$/`. Si coincide, extrae el segmento que corresponde al locale resuelto, con fallback a inglés (`en`) si no se encuentra.

---

## Cadena de resolución de locale

Para cada entrega, Nexus determina el idioma objetivo en este orden de prioridad estricto:

1. **Anulación en el trigger**: La propiedad `_locale` pasada en el objeto `data` del trigger:
   ```ts
   data: {
     _locale: 'es';
   }
   ```
2. **Propiedad del suscriptor**: El campo `locale` en el perfil del suscriptor:
   ```ts
   recipients: [{ externalId: 'user_42', locale: 'es-MX' }];
   ```
3. **Valor por defecto del entorno**: Fallback a **`en`**.

### Reglas de validación

- Las cadenas de locale del suscriptor se validan usando un patrón BCP 47 (`/^[a-z]{2,3}(-[a-zA-Z0-9]{1,8})*$/`). Esto admite locales regionales como `en-US`, `es-MX` y `pt-BR`.
- Al hacer coincidir las claves en `contentTemplates`, el compilador elimina los sufijos regionales (por ejemplo, `es-MX` se resuelve a la clave base `es`).

## Locales base admitidos

Nexus tiene soporte de localización integrado para los siguientes idiomas base:

| Código | Idioma    | Código | Idioma     |
| :----- | :-------- | :----- | :--------- |
| `en`   | English   | `nl`   | Nederlands |
| `es`   | Español   | `tr`   | Türkçe     |
| `fr`   | Français  | `hi`   | हिन्दी     |
| `de`   | Deutsch   | `ar`   | العربية    |
| `pt`   | Português | `ja`   | 日本語     |
| `it`   | Italiano  | `zh`   | 中文       |
| `ko`   | 한국어    |        |            |

## Archivos de traducción vs Plantillas localizadas

Para una organización óptima, combina los archivos de traducción y las plantillas localizadas:

- **Usa plantillas localizadas** (esta función) para layouts estructurales específicos del canal, contenido de email enriquecido o diferencias de layout entre idiomas.
- **Usa [Archivos de traducción](/docs/platform/features/translations)** con el helper `{{ t "key" }}` para cadenas reutilizables compartidas (por ejemplo, pies de página, etiquetas de botones, enlaces de soporte) referenciadas en múltiples workflows.
