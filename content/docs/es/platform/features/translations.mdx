---

Los **archivos de traducción** almacenan cadenas de locale compartidas por entorno. Referencialas en cualquier plantilla de email, SMS o push con `{{ t "key" }}` en lugar de duplicar copias completas de la plantilla por idioma.

<Callout type="info">
  Esto complementa las [Plantillas multi-idioma](/docs/platform/features/i18n), que almacenan
  variantes de locale completas dentro de `contentTemplates`. Usa los **archivos de traducción**
  para cadenas reutilizables compartidas; usa las **plantillas de locale** para diferencias de
  layout completas específicas del canal.
</Callout>

---

## Cómo funciona el helper `t`

Al compilar la plantilla, el helper `{{ t "key" }}` de Handlebars:

1. Resuelve el locale actual del suscriptor (desde la anulación `_locale` → campo `locale` del suscriptor → por defecto `en`)
2. Busca la clave en el archivo de traducción para ese locale
3. Hace fallback al locale base (por ejemplo, `"en"` desde `"en-US"`)
4. Hace fallback a inglés si no se encuentra ninguna coincidencia
5. Devuelve la cadena de la clave sin procesar si no existe ninguna traducción en ningún locale

## Subir traducciones

**Panel de control**: **Templates → Translations** → seleccionar locale → pegar o cargar JSON.

**API de Gestión (clave `sk_*` — para scripts y CI/CD):**

```http
PUT /v1/management/translations
Authorization: Bearer sk_prd_…
Content-Type: application/json
```

**API del panel de control (autenticación JWT — para integraciones de navegador):**

```http
PUT /v1/translations
Authorization: Bearer <jwt_token>
```

**Payload:**

```json
{
  "locale": "es",
  "namespace": "default",
  "content": {
    "welcome_message": "Bienvenido",
    "order_shipped": "Tu pedido ha sido enviado",
    "cta_view_order": "Ver pedido",
    "invoice_due": "Factura vencida"
  }
}
```

El campo `namespace` es una etiqueta para organizar tus claves en el panel de control. Las claves de todos los namespaces están disponibles para el helper `t` independientemente del namespace — la búsqueda de claves es plana en todo el contenido del locale.

---

## Uso en plantillas

```html
<h1>{{ t "welcome_message" }}</h1>
<p>{{ t "order_shipped" }} — {{ data.orderId }}</p>
<a href="{{ data.trackingUrl }}">{{ t "cta_view_order" }}</a>
```

Cuando el locale del suscriptor es `es`, esto renderiza:

```html
<h1>Bienvenido</h1>
<p>Tu pedido ha sido enviado — ORD-12345</p>
<a href="https://track.example.com/xyz">Ver pedido</a>
```

## Orden de resolución de locale

Cuando se envía una notificación, el locale se resuelve en este orden de prioridad:

1. Campo `_locale` en el payload `data` del trigger (anulación por trigger)
2. Campo `locale` del suscriptor (por ejemplo, `"es"`, `"ja"`)
3. Fallback a `"en"` (valor por defecto del entorno)

**Anular el locale en un trigger específico:**

```ts
await nexus.workflows.trigger({
  workflowName: 'order.shipped',
  recipients: [{ externalId: 'user_42' }],
  data: {
    _locale: 'es',
    orderId: 'ORD-12345',
  },
});
```

## Organizar claves con namespaces

Los namespaces son una herramienta organizativa opcional para agrupar cadenas relacionadas en el panel de control. **No** afectan cómo se referencian las claves en las plantillas.

**Buena práctica**: Usa una convención de nomenclatura de claves que implique el namespace, como `billing_invoice_due` o `auth_login_prompt`:

```json
{
  "locale": "ja",
  "namespace": "billing",
  "content": {
    "billing_invoice_due": "請求書の支払期限",
    "billing_pay_now": "今すぐ支払う"
  }
}
```

En las plantillas: `{{ t "billing_invoice_due" }}` (búsqueda de clave plana simple).

## Flujo de trabajo con CLI

Gestiona los archivos de traducción desde la línea de comandos:

```bash
# Descargar todas las traducciones actuales a archivos JSON locales
nexus translations pull --locale es --output ./translations/es.json

# Subir traducciones actualizadas
nexus translations push --locale es --input ./translations/es.json
```

---

## Locales admitidos

Se admite cualquier cadena de locale BCP 47 (por ejemplo, `en`, `en-US`, `es`, `es-MX`, `ja`, `pt`, `pt-BR`, `fr`, `de`, `zh-CN`). El helper `t` elimina el sufijo de la región y hace fallback al locale base si no se encuentra un archivo específico de la región.
