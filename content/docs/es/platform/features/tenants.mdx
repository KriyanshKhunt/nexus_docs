---
title: Branding por Tenant
description: Notificaciones white-label para SaaS B2B — cada uno de tus clientes obtiene branding aislado, preferencias y feeds de notificaciones.
---

Los **tenants** representan _tus clientes_ dentro de Nexus (distintos de tu **Organización** de Nexus, que es tu espacio de trabajo). Usa tenants cuando tu producto sirve a múltiples empresas que necesitan emails con su propia marca, feeds in-app con alcance limitado y preferencias de notificación aisladas.

<Callout type="info">
  Los tenants son una funcionalidad **B2B**. Si tu app está orientada al consumidor con una sola
  marca, no necesitas tenants.
</Callout>

---

## Modelo del tenant

| Campo                   | Tipo   | Descripción                                                      |
| :---------------------- | :----- | :--------------------------------------------------------------- |
| `externalId`            | string | El ID de tu cliente (por ejemplo, `"tenant_acme"`)               |
| `name`                  | string | Nombre para mostrar                                              |
| `branding.logo`         | string | URL del logo                                                     |
| `branding.primaryColor` | string | Color hexadecimal para los elementos de acento                   |
| `branding.footerHtml`   | string | Pie de página HTML personalizado en los layouts de email         |
| `properties`            | object | Pares clave-valor de formato libre para metadatos personalizados |

---

## Crear o actualizar un tenant

Los tenants se crean o actualizan mediante upsert — llamar a `upsert` con un `externalId` existente actualiza sus campos.

**SDK de Node:**

```ts
await nexus.tenants.upsert({
  externalId: 'tenant_acme',
  name: 'Acme Corp',
  branding: {
    logo: 'https://cdn.acme.io/logo.png',
    primaryColor: '#2563eb',
    footerHtml: '<p>© 2026 Acme Corp. All rights reserved.</p>',
  },
  properties: { tier: 'enterprise', region: 'us-east' },
});
```

**API de Gestión (clave `sk_*`):**

```http
PUT /v1/management/tenants
Authorization: Bearer sk_prd_…
Content-Type: application/json

{
  "externalId": "tenant_acme",
  "name": "Acme Corp",
  "branding": {
    "logo": "https://cdn.acme.io/logo.png",
    "primaryColor": "#2563eb",
    "footerHtml": "<p>© 2026 Acme Corp</p>"
  }
}
```

## Disparar con contexto de tenant

Pasa `tenant` como la cadena `externalId` en cualquier trigger de workflow:

```ts
await nexus.workflows.trigger({
  workflowName: 'invoice.sent',
  tenant: 'tenant_acme',
  recipients: [{ externalId: 'user_42', email: 'billing@acme.io' }],
  data: { invoiceId: 'INV-001', amount: 4900 },
});
```

Cuando se establece un `tenant` en el trigger:

- Los layouts de email se compilan con las variables de branding del tenant (`{{ logo }}`, `{{ primaryColor }}`, etc.)
- Las notificaciones in-app tienen el alcance limitado al feed del tenant

---

## Cómo se inyecta el branding en los layouts de email

Los campos de branding del tenant se expanden directamente en el contexto de la plantilla de Handlebars al compilar los layouts de email. Referencialos por sus nombres de campo — **sin** el prefijo `branding.`:

```html
<!-- En el HTML de tu layout de email -->
<img src="{{ logo }}" alt="{{ name }} logo" />
<div style="background-color: {{ primaryColor }};">{{{ content }}}</div>
{{{ footerHtml }}}
```

<Callout type="info">
  `{{{ content }}}` (llaves triples) renderiza el cuerpo de la plantilla de email compilada como HTML sin procesar dentro del layout. `{{ logo }}`, `{{ primaryColor }}` y `{{ footerHtml }}` se inyectan desde el objeto de branding del tenant.
</Callout>

## Feed de notificaciones in-app con alcance por tenant

Si consultas la API del SDK raw directamente, puedes filtrar notificaciones por el UUID de base de datos del tenant:

**API del SDK:**

```http
GET /v1/sdk/notifications?subscriberExternalId=user_42&tenantId=tenant_database_uuid
```

<Callout type="warn">
  El parámetro de consulta del SDK `tenantId` requiere el **UUID de base de datos interno** del
  tenant, no su ID externo. Los componentes del SDK frontend (React, Angular, JS) no admiten la
  limitación de feeds por tenant de forma nativa. Usa etiquetas de topics de workflow si necesitas
  feeds de inbox con alcance por categoría simples en la interfaz de usuario.
</Callout>

## Listar tenants

```ts
const { data } = await nexus.tenants.list({ page: 1, limit: 25 });
```

## Límites

| Límite                           | Valor |
| :------------------------------- | :---- |
| Máximo de tenants por entorno    | 1,000 |
| Máximo de campos de branding     | 20    |
| Máximo de claves de `properties` | 50    |
