title: Rich In-App Inbox

---

El inbox in-app admite un payload de notificación enriquecido que incluye botones de acción, avatares de actores, redirecciones al hacer clic y filtrado de etiquetas basado en topics — todo configurado al momento del trigger mediante claves especiales con prefijo `_` en el campo `data`.

---

## Actor (quién causó la notificación)

Pasa metadatos del actor usando la clave `_actor` en el `data` del trigger para mostrar quién inició el evento:

```ts
await nexus.workflows.trigger({
  workflowName: 'comment.added',
  recipients: [{ externalId: 'user_42' }],
  data: {
    _actor: {
      name: 'Sarah Chen',
      avatar: 'https://cdn.example.com/avatars/sarah.jpg',
      id: 'user_sarah',
    },
    commentPreview: 'Looks good to me!',
  },
});
```

El actor se renderiza como un avatar con nombre en el feed del inbox ("Sarah Chen commented…"). Los tres campos del actor son opcionales.

| Campo de `_actor` | Tipo   | Descripción                                 |
| :---------------- | :----- | :------------------------------------------ |
| `name`            | string | Nombre para mostrar junto a la notificación |
| `avatar`          | string | URL a la imagen del avatar                  |
| `id`              | string | ID externo del actor (para enlazar)         |

## Botones de acción

Incluye hasta **2 botones de acción** usando `_actions` en el `data` del trigger:

```ts
await nexus.workflows.trigger({
  workflowName: 'approval.requested',
  recipients: [{ externalId: 'user_42' }],
  data: {
    _actions: [
      { label: 'Approve', url: '/api/approve/req_123', variant: 'primary' },
      { label: 'Decline', url: '/api/decline/req_123', variant: 'secondary' },
    ],
    requestId: 'req_123',
  },
});
```

| Campo de `_actions` | Tipo                         | Descripción                                     |
| :------------------ | :--------------------------- | :---------------------------------------------- |
| `label`             | string                       | Texto del botón (máximo 50 caracteres)          |
| `url`               | string                       | URL de la acción — relativa (tu app) o absoluta |
| `variant`           | `'primary'` \| `'secondary'` | Estilo del botón (por defecto `'primary'`)      |

<Callout type="info">
  Solo se renderizan las primeras 2 acciones — los elementos adicionales se ignoran silenciosamente.
</Callout>

## Redirección al hacer clic

Controla a dónde navega la notificación cuando se hace clic usando `_redirect`:

```ts
data: {
  _redirect: {
    url: '/orders/ord_789',
    target: '_self',   // '_self' (por defecto) o '_blank'
  },
}
```

O como una cadena simple para navegación básica:

```ts
data: {
  _redirect: '/orders/ord_789',
}
```

## Filtrado por etiquetas

Las etiquetas provienen del **nombre del topic del workflow** — asigna un topic a un workflow en el panel de control, y todas las notificaciones de ese workflow llevarán ese topic como etiqueta.

### Filtrado por etiquetas con el SDK de React

En el SDK de React, el componente `NotificationInbox` filtra las notificaciones del lado del cliente usando la prop `tag`:

```tsx
<NotificationInbox tag="billing" />
```

Construye una interfaz de usuario de pestañas personalizada pasando un valor de estado a la prop `tag`:

```tsx
const [activeTag, setActiveTag] = useState<string | undefined>(undefined);

<>
  <button onClick={() => setActiveTag(undefined)}>All</button>
  <button onClick={() => setActiveTag('billing')}>Billing</button>
  <button onClick={() => setActiveTag('mentions')}>Mentions</button>
  <NotificationInbox tag={activeTag} />
</>;
```

### Filtrado con la API SDK raw y el SDK Headless JS

Para integraciones headless personalizadas, las etiquetas se pueden filtrar en el lado del servidor:

- **API SDK raw**: Consulta el endpoint con el parámetro de consulta `tag` o `tags`:
  ```http
  GET /v1/sdk/notifications?subscriberExternalId=user_42&tag=billing
  ```
- **SDK Headless JS**: Pasa la opción del array `tags`:
  ```ts
  await nexus.notifications.refetch({ tags: ['billing'] });
  ```

## Estados del ciclo de vida de la notificación

| Estado                   | Significado                                                           |
| :----------------------- | :-------------------------------------------------------------------- |
| **Sin leer (Unread)**    | Entregada, no abierta — incrementa el conteo de insignia de no leídas |
| **Leída (Read)**         | El usuario hizo clic o marcó explícitamente como leída                |
| **Archivada (Archived)** | Oculta del feed activo — aún recuperable                              |
| **Vista (Seen)**         | El SDK ha renderizado el elemento en el viewport                      |

Sincronización entre dispositivos: marcar una notificación como leída en un dispositivo limpia la insignia en todos los demás vía WebSocket broadcast.

## Acceso al SDK Headless

```ts
// Obtener con filtro de etiqueta
await nexus.notifications.refetch({ tags: ['billing'] });

// Cargar la siguiente página
await nexus.notifications.loadMore({ tags: ['mentions'] });

// Marcar acciones
await nexus.notifications.markRead(notificationId);
await nexus.notifications.markAllRead();
await nexus.notifications.archive(notificationId);
```

Construye una interfaz de usuario completamente personalizada con [`@nexus-signal/js`](/docs/sdk/frontend/js) mientras Nexus gestiona el estado del WebSocket.
