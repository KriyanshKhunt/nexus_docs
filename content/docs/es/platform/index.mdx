# Plataforma Nexus Signal

**Nexus Signal** es una infraestructura de notificaciones orientada a desarrolladores. Una API unificada y un lienzo visual de flujos de trabajo enrutan mensajes a través de **10 canales** mientras conservas **tus propias claves de proveedor**, evitando recargos por mensaje y el secuestro del proveedor (vendor lock-in).

Piensa en Nexus como tu plano de control centralizado de notificaciones, orquestando la entrega desde los eventos desencadenantes (triggers) iniciales hasta los callbacks de producción.

## Diferencias principales

| Capacidad                      | Beneficio para el desarrollador y el negocio                                                                                                                                |
| :----------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Supresión por presencia**    | Omite push/SMS redundantes si el usuario tiene una sesión de WebSocket activa en la aplicación, reduciendo significativamente el gasto en operadores.                       |
| **Envío inteligente con IA**   | Analiza automáticamente la actividad del usuario para entregar resúmenes de notificaciones o mensajes durante su hora pico de engagement.                                   |
| **Arquitectura BYOP**          | Conecta las credenciales de SendGrid, Twilio, Resend y SNS directamente. Paga a los operadores a precio de costo con control absoluto.                                      |
| **Análisis de costos**         | Seguimiento detallado del gasto por proveedor, canal y evento de flujo de trabajo individual con alertas de límite de presupuesto automatizadas.                            |
| **Flujos de trabajo visuales** | Compone árboles de pasos con retrasos, regulaciones (throttles), pruebas A/B, filtros condicionales, nodos HTTP Fetch y generadores de contenido LLM.                       |
| **Fan-out de objetos**         | Notifica a todos los suscriptores de un proyecto, documento, equipo o problema con un solo payload de trigger sin consultas de búsqueda manuales en la base de datos.       |
| **Multi-tenancy B2B**          | Plantillas de correo marca blanca, personalización de marca integrada (in-app branding) y preferencias de entrega por organización cliente (tenant).                        |
| **Herramientas de CLI y MCP**  | Administra flujos de trabajo como código bajo control de versiones e intégrate con asistentes de codificación de IA (como Cursor, Claude Code) a través de un servidor MCP. |

## Diez canales, una sola API de trigger

En lugar de gestionar de forma individual integraciones personalizadas para correo electrónico, SMS, Web Push, Mobile Push, campanas integradas (In-App Bells), WhatsApp, Slack, Discord, Microsoft Teams y Webhooks, emites un único evento a Nexus:

```ts
import { NexusClient } from '@nexus-signal/node';

const nexus = new NexusClient({ secretKey: process.env.NEXUS_SECRET_KEY! });

await nexus.workflows.trigger({
  workflowName: 'order.shipped',
  recipients: [{ externalId: 'user_42', email: 'alex@acme.io' }],
  tenant: 'tenant_acme_corp', // Limita el estilo y las preferencias a este tenant cliente
  data: {
    customerName: 'Alex',
    orderId: 'ord_990142',
    trackingNumber: '1Z999AA10123456784',
  },
});
```

El endpoint del trigger devuelve un payload **HTTP 202 Accepted** en menos de 10 ms. La plataforma encola el evento en una cola resiliente basada en Redis donde los workers procesan las reglas de tus pasos, compilan plantillas localizadas y enrutan los mensajes a tus proveedores.

## Flujo de ejecución de alto nivel

```mermaid
flowchart TD
    App[Tu Backend SDK] -->|POST trigger event| API[Express API Gateway]
    API -->|1. Validar Clave API y Esquema| DB[(PostgreSQL)]
    API -->|2. Encolar Trabajo de Ingestión| Q[Redis / BullMQ]
    API -->|3. Sub-10ms 202 Accepted| App
    Q --> Worker[Async Worker Cluster]
    Worker -->|Leer Preferencias del Suscriptor| DB
    Worker --> Presence{¿Usuario en línea?}
    Presence -->|Sí| InApp[In-App WebSocket Gateway]
    Presence -->|No / Fallback| Carriers[Weighted Provider Dispatcher]
    Carriers --> CarrierAPIs[SendGrid / Twilio / FCM / Resend]
```

## Stack tecnológico

El host de Nexus Signal está construido utilizando componentes web estándar de alto rendimiento:

- **API Gateway**: Node.js y Express
- **Bases de datos**: PostgreSQL (a través de Prisma ORM) y Redis (almacenamiento en caché y pub/sub)
- **Gestor de colas**: BullMQ (enrutamiento de contrapresión, reintentos retrasados)
- **Tiempo real**: Socket.IO (motor de conexión WebSocket para campanas integradas)
- **Componentes de interfaz**: React y Tailwind CSS
